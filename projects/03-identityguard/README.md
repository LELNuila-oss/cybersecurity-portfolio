# IdentityGuard — Enterprise IAM/IGA Lab

**Status:** Phase 0 — Market & Problem Definition (in progress). **No software implemented.**

IdentityGuard is a planned vendor-neutral portfolio laboratory designed to illustrate how a fictional organization with approximately 300 synthetic employees might govern identity and access from onboarding through offboarding. It is not a replacement for SailPoint, and it is not an actual enterprise deployment.

## Business problem

Inconsistent Joiner–Mover–Leaver (JML) operations can leave stale access, orphaned accounts, and weak audit trails. IdentityGuard will *eventually* simulate HR-driven access decisions, role-based access controls, approvals, reconciliation, access reviews, and risk detection.

## Why this project?

A targeted October 2026 research report surveyed 20 IAM/IGA job postings. Explicit mentions included SailPoint (15/20), IGA/governance (15/20), integration/directories/APIs (9/20), JML/provisioning (8/20), audit/compliance (8/20), RBAC/SoD/least privilege (7/20). These are counts from a non-representative sample, not general-market statistics. The exported research report does not contain complete direct URLs for all 20 postings; link-level validation remains pending.

## Working principles

1. Business risk and measurable acceptance tests before code.
2. Synthetic data only; no employee information or real credentials.
3. Clearly distinguish planned features from tested implementations.
4. Local-first and low-cost where possible (Zorin OS / Linux).
5. Never claim hands-on SailPoint production experience or affiliation with any employer.

**Phase 0 in progress.** Phase 1 requires explicit approval from the project owner. Documentation drafts are not evidence of implementation.
